## 2. What this repo is

This repo is a free, standalone internal NK AI Market Brief MVP. It produces a daily market brief focused only on AI plus fashion, beauty, e-commerce, agentic commerce, AI shopping, and AI agents or assistants used by major fashion, beauty, retail, and commerce platforms or brands. The default mode uses Google News RSS metadata, deterministic filtering/scoring, local/static outputs, GitHub Actions artifacts, no secrets, no database, no LLM, and no page scraping.

User-facing artifacts:
- Local preview: `npm run preview`
- Public daily refresh: `npm run daily`
- Build static site: `npm run build`
- Deploy check: `npm run check:deploy`
- Machine status/integrity/query: `npm run logs:status`, `npm run logs:verify`, `npm run logs:query`
- Optional send: `npm run send`
- Outputs: `.newsletter-outbox/YYYY-MM-DD/newsletter.html`, `.newsletter-outbox/YYYY-MM-DD/newsletter.txt`, `.newsletter-outbox/YYYY-MM-DD/run.json`, `site/index.html`, `site/newsletter.txt`, `site/run.json`, `.newsletter-logs/YYYY-MM-DD/<run-id>/{events.jsonl,run-manifest.json,summary.json}`, and `.newsletter-logs/commands.jsonl`
- GitHub repository: `https://github.com/OsanGen/nk-ai-market-newsletter` (private)
- Live review page: `https://osangen.github.io/nk-ai-market-brief-review/`
- Public workflow-capable Pages repo: `https://github.com/OsanGen/nk-ai-market-brief-review`
- Cyril evidence pack: `CYRIL_VERIFICATION_PACK.md`
- Share instructions: `SHARE_WITH_CYRIL.md`

## 3. System map

Components:
- `newsletter-sources.json`: nine original source definitions from the NK context plus three review-yield market scan source definitions.
- `src/config.mjs`: no-secret defaults, comma-separated recipient parsing, optional env parsing, daily lookback windows, 4 a.m. America/New_York target hour, and review-mode lookback.
- `src/sources.mjs`: source registry validation and disabled-source filtering.
- `src/google-news.mjs`: Google News RSS URL construction.
- `src/fetch-feeds.mjs`: RSS fetch/parse with `rss-parser`, built-in `fetch`, 15-second source timeout, safe error code/fingerprint, per-source duration events, and aggregate source health.
- `src/observability/*`: versioned compact JSONL contract, AsyncLocalStorage run context, automatic component discovery, recursive redaction, atomic manifests/summaries/latest pointer, standalone command events, exact-run query/verification, and SHA-256/byte integrity.
- `src/run-health.mjs`: pipeline/content/deployment/live health separation and failed-pipeline command gating.
- `src/run-receipt.mjs`: explicit nested allowlist plus recursive sanitization for public `site/run.json`.
- `src/normalize.mjs`: normalized RSS item shape, actual RSS outlet extraction, tag stripping, display-text neutralization, escaping helpers, and URL safety.
- `src/filter-score.mjs`: strict title/summary inclusion/exclusion using word/phrase-boundary matching so source categories or substrings like `ai` inside `retail`/`openai` cannot admit generic news.
- `src/dedupe.mjs`: canonical URL and title-overlap dedupe.
- `src/story-diversity.mjs`: review story selection that caps repeated topic clusters at two when enough qualifying items exist and prefers source/category diversity for close scores.
- `src/summarize.mjs`: deterministic RSS-only headline, outlet suffix cleanup, non-duplicative summary fallback, issue-level copy rotation, business-facing why-it-matters, and category fields.
- `src/render-html.mjs` and `src/render-text.mjs`: escaped/neutralized email-style HTML and text rendering.
- `src/review-status.mjs`: review readiness and limited-yield state from selected item count.
- `src/automation-status.mjs`: workflow automation detection for daily 4 a.m. retry/watchdog schedules, retained machine evidence, artifact upload, Pages deploy support, and manual-push status.
- `src/live-freshness.mjs`: local-date freshness evaluation for the live Pages `run.json`, with exact expected run ID, mode/lookback/automation/pipeline/all-source/send-disabled checks.
- `src/render-review-page.mjs`: escaped static review page rendering for `site/index.html`, including noindex metadata, status badges, review status, selected-signal label, lead story, story grid when available, actual outlet source labels, scan labels, visually secondary technical diagnostics, source fetch status, automation status, and `newsletter.txt` link.
- `src/send-resend.mjs`: optional Resend HTTP API send gate, disabled by default, minimum-item check, recipient validation, idempotency header, and fingerprint-only provider message evidence.
- `src/time-guard.mjs`: 4 a.m. America/New_York daily target guard for non-forced auto sends.
- `src/run-newsletter.mjs`: correlated phase/event orchestrator, detailed private output writer, sanitized public receipt writer, and terminal run finalizer.
- `scripts/*.mjs`: npm entrypoints for preview, persistent schedule decision, public daily refresh, build, explicit send, deploy/live checks, and machine status/integrity/query.
- `.github/workflows/newsletter.yml`: manual/scheduled CI, persistent freshness gate, tests, daily public output for scheduled `auto`, exact-run log verification under `always()`, fresh-date/health deploy checks, 30-day private evidence artifacts, optional Pages deployment gated by `DEPLOY_GITHUB_PAGES=true`, and live verification evidence.

Data flow: enabled sources -> RSS fetch/parse with source events -> normalized items -> strict filter/score -> dedupe/selection/summaries -> four-axis health + review/automation status -> rendered outputs -> detailed private outbox + integrity-checked private JSONL/manifest/summary + sanitized public receipt/site -> exact-run log verification -> deploy guard -> retained artifact and optional GitHub Pages -> live verification event -> optional gated send outside the default public workflow.

Trust boundaries: external RSS/live JSON is untrusted; credentials and recipients remain private env inputs; `.newsletter-logs` and detailed outbox are private operational evidence; `site/` receives only allowlisted state; configured deployment is not treated as live proof.


Explicit send failure proof:
```bash
NEWSLETTER_SEND_ENABLED=true npm run send || true
```

Shareable review page proof:
```bash
npm run build
npm run check:deploy
```

Optional send command:
```bash
npm run send
```

Environment:
- Default mode requires no secrets.
- `.env.example` documents optional email settings and defaults to `NEWSLETTER_SEND_ENABLED=false`.
- `.env.example` documents optional `NEWSLETTER_LOG_DIR=.newsletter-logs`; the log root is gitignored and must remain outside `site/`.
- Preview/build mode uses `NEWSLETTER_REVIEW_LOOKBACK_HOURS=168` by default so the review page can show enough qualifying signals. Scheduled `auto` mode keeps `NEWSLETTER_LOOKBACK_HOURS=36` and `NEWSLETTER_MONDAY_LOOKBACK_HOURS=84`.
- `npm run daily` is the public scheduled page path: it forces `auto` mode, keeps sending disabled, and uses the normal daily lookback windows so delayed GitHub cron starts still publish generated output.
- Preview mode cannot send.
- Email cannot send unless all gates pass: `NEWSLETTER_SEND_ENABLED=true`, send/auto mode, `RESEND_API_KEY`, `NEWSLETTER_FROM`, valid `NEWSLETTER_TO`, and enough items.
- Default GitHub Actions workflow runs from the default branch every day on redundant 4 a.m. America/New_York coverage schedules `2,7,12,17,22,27,32,37,42,47,52,57 8,9 * * *` and watchdog schedule `17 10,11,12 * * *`, supports manual dispatch with `mode`, runs `npm run should:refresh` to skip duplicate retries once the live page is fresh, uses `npm run daily` plus mode/lookback/fresh-date deploy guards for scheduled public output, supports Pages deploy when `DEPLOY_GITHUB_PAGES=true`, verifies live freshness after deploy, and keeps email disabled by default.
